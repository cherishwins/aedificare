Instruction files buy efficiency and behaviour, not correctness. Repository overviews, the thing
/init writes, did not help. Non-standard rules did. Anthropic's own April postmortem: a terse-output

THE LADDER FOR EXTERNAL SYSTEMS




1             CLI in Bash. gh, vercel, wrangler, psql, git, npx @osdk/cli. No per-tool listing at all. Output lands wherever you pipe it.

2             Code-mode or meta-tool MCP. Cloudflare's three-tool server runs JavaScript against its API spec: 244,000 tokens of naive tools
              becomes 1,100. Atlassian ships discover plus execute. Palantir MCP starts with one tool, search_tools.

3             Remote HTTP MCP with OAuth. Where the CLI is weak or scoped auth matters: Figma, Notion, Linear, Supabase read-only, Neon,
              Vercel. Stateless HTTP only; the 2026-07-28 spec removed sessions.

4             Local stdio MCP. Only when nothing above exists. Reference servers are not hardened: the filesystem and git servers each
              shipped CVEs. Never install a filesystem MCP inside Claude Code; it already has Read, Edit, Grep and Bash.

PALANTIR FOUNDRY, AS OF OCTOBER 2026   B




AI FDE has no API.

Palantir's in-platform builder agent went GA on 12 March 2026. It is a chat window. No MCP tool, no
CLI, no endpoint. The one programmatic hook is a browser pre-fill URL, and tool approvals still happen
in the browser.
So "my local Claude Code drives AI FDE agent to agent" is not a thing you can build this quarter. What
Palantir built instead is better for a solo developer, because it has fewer moving parts.

THE MONDAY SETUP, IN ORDER




1             CLAUDE.md under 200 lines: build and test commands, the host names, the rules the model cannot infer. One
              .claude/rules file per sub-system with paths: .

2             Install the CLIs. gh, vercel, wrangler, the vendor database client. Confirm each works in Bash before any server is added.

3             Commit a .mcp.json with only what the ladder justifies, slim profiles on, tool search on. Then run /context all and read
              the bill.

4             Three skills with explicit trigger words: the deploy path, the review path with context: fork , the thing you do weekly and
              keep re-explaining.

5             Hooks for the guarantees: format on edit, block pushes to main, a Stop hook that runs the suite and greps the output down to
              the failures.

6             Turn the sandbox on. Pick model and effort. Then, and only then, send the first message.




23
EVERYTHING ABOVE HAS A HALF-LIFE




Every harness component is an assumption about what
the model cannot do.



Anthropic's context resets, built for Sonnet 4.5, were dead weight on Opus 4.5 and removed. Their
sprint contracts lasted one generation. The default effort level changed twice this year and one of the
changes was a mistake they reversed.
So the setup needs a ritual, not a config: on each model release, remove one component at a time and
re-run the three skills and the Stop hook. Keep what still earns its tokens. The source files behind this
deck list fifteen things we could not verify, so you know where the edges are.
