Step one

Six jobs. Pick the job before the tool.

Most bloated setups are two tools fighting over one job. These are the six jobs a Claude Code setup has to do, and what Claude Code already gives you for each.

Always on

CLAUDE.md · rules without paths

Loads every turn. Keep it under 200 lines and only write what the model can't guess. B

On demand

Skills

Name and description always, body only when called. Model-triggered skills fire unreliably; use explicit trigger words. B

Guarantee

Hooks · 33 events

The only layer that enforces. Format on edit, block pushes to main, run tests on stop. B

Isolation

Subagents · worktrees

Fresh context window, summary back. Use for investigation and review, not for sequential coding. B

Outside world

CLI · MCP servers

Everything below. CLI first, MCP when the CLI is weak or auth matters. B

Proof

Stop hook · reviewer subagent

A test the model can't talk its way past. The cheapest tokens you will spend. B

The ladder

CLI first.

"CLI tools are the most context-efficient way to interact with external services." Anthropic, Claude Code best practices.

1

CLI in Bash

gh, vercel, wrangler, psql, git, npx @osdk/cli. No tool listing at all; output goes wherever you pipe it.

2

Code-mode MCP

A few tools front a whole API. Cloudflare's three-tool server: about 244,000 tokens of naive tools becomes about 1,100. Palantir MCP's tool search starts with one tool.

3

Remote MCP with OAuth

Where the CLI is weak or scoped auth matters: Figma, Notion, Linear, Supabase read-only, Vercel. Stateless HTTP; the 2026-07-28 spec removed sessions.

4

Local stdio MCP

Only when nothing above exists. Reference servers are not hardened: the filesystem and git servers both shipped CVEs.

Palantir Foundry

The plan was two AIs talking.

Claude Code in the terminal writing the app, Palantir's AI FDE inside Foundry building the data platform, coordinating agent to agent.

AI FDE has no API.

It is a chat window. No MCP tool, no CLI, no endpoint. The one hook is a browser link that pre-fills a prompt, and a human still approves. B

Palantir MCP

GA 2026-06-25 · about 90 tools · stdio · user token

Claude Code does the build work from your IDE: object, link and action types on a branch, proposals, Python transform repos, dataset builds, OSDK versions. It cannot write ontology data and has no merge tool; you approve proposals in the UI. B

Ontology MCP

GA 2026-06-25 · per Developer Console app · HTTP · OAuth

The consumer side: object types as a SQL tool, every action type as its own tool, query functions as tools. The only MCP route that writes data or triggers logic inside Foundry. B

Your own agent

Claude Agent SDK template · publish with a git tag

The real agent-to-agent path. A Foundry-hosted agent pre-wired to OSDK, Ontology MCP and Palantir MCP with scoped permissions. Wrap it in an action; Claude Code fires the action and reads results back from objects. B

claude mcp add palantir-mcp --scope project \
  -e FOUNDRY_TOKEN='${FOUNDRY_TOKEN}' \
  -- npx -y palantir-mcp --foundry-api-url https://$FOUNDRY_HOST --tool-search

Free developer tier: 60 action types, about 5 users, no client-credentials OAuth (so no headless service user), and beta apps such as the Foundry CLI need a support ticket. B
